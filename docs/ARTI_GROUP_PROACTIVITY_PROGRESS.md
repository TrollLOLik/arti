## Исполняемый контракт

`topic_id=-1` — неизвестная тема, `0` — наблюдаемая обычная группа, положительное значение — конкретная форумная тема. Старые события не становятся публичными автоматически. Group prompt получает только разрешённые наблюдения своей темы. Legacy RAG в группе не используется, поскольку его записи не имеют надёжной аудитории и темы. Это осознанно ограничивает доступную память; будущие общегрупповые знания требуют отдельного подтверждённого продвижения источников.

Рабочее окно: до 64 сообщений, 8 веток и 16 вопросов. Арбитр получает до 32 сообщений с лимитом 12 000 UTF-8 байт для сообщений; исходный повод сохраняется при обрезке. Реплика — до 600 символов. Очередь автономных кандидатов ограничена 64 на тему и 128 на группу. Первое ожидание — 12–45 секунд по наблюдаемому темпу; срок обычного кандидата — пять минут; повторное ожидание ограничено двумя отсрочками.

По умолчанию: три инициативы за скользящие 24 часа, интервал 900 секунд, доля сообщений Арти до 15%, до 12 оценок кандидатов в час на группу. Отказы модели расходуют бюджет оценок. Выбранное shadow-действие расходует бюджет участия так же, как предполагаемая отправка. Реакции не обходят квоты. У темы могут быть более строгие лимиты; общий бюджет группы ограничивает сумму действий по темам.

Одна оценка или генерация имеет до двух provider attempts с таймаутом 90 секунд на попытку. Арбитр вызывается после правил, генератор — после допуска. Оценки и генерация не выполняются внутри SQL-транзакции. Нормы повышают осторожность, но не выдают разрешение. LLM-оценки usefulness/confidence не являются откалиброванными вероятностями.

Согласованное напоминание отличается от свободной инициативы: срок не переносится автоматически из-за социальных quiet hours, mentions-only или квоты спонтанных реплик. Пауза, выключатель, `/stop`, недоступный источник и отсутствие участника продолжают действовать. После снятия паузы неотправленный кандидат напоминания может быть восстановлен в пределах 24 часов от срока; подтверждённые и неоднозначные доставки не повторяются. RP-обязательство использует сцену и настройки своей темы.

Редактирование заменяет публичное наблюдение и отменяет ожидающие кандидаты по старой версии. Историческое raw-событие остаётся отдельным неизменяемым источником; edit не равнозначен `/forget`. Забывание удаляет публичные проекции, зависимые кандидаты и обратную связь, а также подавляет собственные ответы, использовавшие источник. Telegram не сообщает универсально обо всех удалениях: неизвестное удаление нельзя гарантированно обнаружить до отказа reply anchor.

Срок `retention_days` ограничивает публичное рабочее окно и удаление текстовых payload из `group_observations`; он **не является** отдельным сроком физического удаления всего когнитивного ledger и legacy-таблиц. Для удаления исходных сведений действует существующий механизм забывания. Логи решений и оперативная диагностика не экспортируют сырой личный текст.

## Проверки и результаты

Медиапуть использует ту же явную адресацию. Голосовые в группе требуют reply к Арти, обращения в подписи или уже выбранного flow; имя, произнесённое только внутри аудио, не обнаруживается без транскрипции. Неадресованные голосовые не скачиваются и не передаются STT автоматически. Нажатие кнопки собственного media flow считается явным запросом участника.

Общая регрессия: **195/195**, без ошибок и пропусков, 140,93 секунды. Точные результаты: [automated_tests_full.json](evaluation/automated_tests_full.json). Все DB-тесты используют отдельные `arti_cognition_test_<uuid>`, создаваемые и удаляемые тестовым процессом; provider calls в общей регрессии — 0.

Проверены разные темы и авторы, персональный отказ, цитаты и риторические вопросы, человеческий ответ до оценки и во время генерации, смена политики, потеря lease, два worker, общий бюджет, backpressure, отключение ответов, неизвестная доставка и рестарт, реакции, забывание поддержки другого автора, anonymous ingress, scopes очереди и пользовательских flow, RP-напоминание, миграция chat ID и общий выключатель.

Человеческая уместность не измерялась. Сравнение с прежним порогом и ablation по нормам/модели беседы остаются исследовательской частью пилота.

## Запуск и управление

1. До эксплуатации сохранить резервную копию обычным порядком. Выполнить проверки:

   ```powershell
   python -m tools.run_cognition_tests
   python -m tools.evaluate_groups
   python -m tools.cognition_admin verify-copy
   ```

   Live synthetic evaluation запускается отдельно и расходует API:

   ```powershell
   python -m tools.evaluate_groups --live --fixture tests/fixtures/group_held_out.json --output docs/evaluation/group_held_out_live.json
   ```

2. Применить миграцию по существующему runbook. `008` добавляется после прежних SQL, применённые файлы не меняются. `cognition_admin status` также вызывает `ensure_schema`, поэтому это не read-only команда для ещё не мигрированной рабочей БД. Во время реализации использовался `verify-copy`, читающий рабочую БД в read-only consistent transaction.

3. В выбранной группе администратор проверяет видимость и задаёт политику. Инициативы исходно выключены: mentions + shadow + full_visibility=false. Пример последовательности для наблюдения:

   ```text
   /proactivity visibility full
   /proactivity tz Asia/Yekaterinburg
   /proactivity hours 23 9
   /proactivity limits 3 900
   /proactivity assessments 12
   /proactivity group useful shadow
   ```

   `visibility full` проверяется через Telegram; сам текст участника не меняет политику. Перед спонтанным действием видимость проверяется снова. Команды меняют правила только после серверной проверки статуса администратора/создателя группы; персональный privileged ID не заменяет эту проверку.

4. После проверки shadow выбранную тему включить явно:

   ```text
   /proactivity topic useful live
   ```

   Эта команда активирует когнитивный контекст текущей темы и режима, не все темы автоматически. Для существующего контекста можно использовать CLI `authority --chat-id <id> --topic-id <thread> --mode default --value active`. Для RP также нужен точный scene ID. Социальный режим: `/proactivity topic social live`; реакции и topic seeds включаются отдельно. Seeds используют явный публичный повод к новой теме, а не случайный push после тишины.

   Для согласованных напоминаний без свободных инициатив подходит `/proactivity topic mentions live`. В shadow и при shadow authority автоматическая доставка обязательств также не исполняется.

5. Быстрое отключение всех самостоятельных действий группы, включая напоминания:

   ```text
   /proactivity group off
   ```

   Выключатель действует поверх исключений тем и не останавливает прямые ответы. `/proactivity group on` снимает выключатель, сохраняя выбранные режимы. `/quiet 60` ставит текущую тему на паузу; `/quiet 0` снимает её. `/stop` отключает ответы и проверяется непосредственно перед автономной отправкой. `/proactivity optout` и `optin` задают персональные ограничения, не меняя режим всей группы.

6. `python -m tools.cognition_admin status` показывает статусы кандидатов и причины решений. При `delivery_unknown` не отправлять автоматически повторно; проверить фактическое действие и закрыть слот существующей командой `cancel-unknown`. Подтверждённая доставка после сбоя восстанавливается как delivered. При смене chat ID ожидающие действия отменяются, старое согласие и история автоматически не переносятся.

Групповой пилот требует согласованного чата, доступной видимости, периода наблюдения и обратной связи людей. Между финальной SQL-проверкой и внешним Telegram существует небольшой неизбежный интервал; общая транзакция с чужой беседой недоступна. Реализация не заявляет биологическую достоверность модели или доказанную уместность в любых группах.
