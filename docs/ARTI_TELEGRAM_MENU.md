# Меню Арти в Telegram

Дата: 2 октября 2026 года. Это интерфейс внутри Telegram с inline-кнопками, без Mini App. Рабочий бот в ходе реализации не запускался, рабочая база не менялась.

## Как открыть

Кнопка меню Telegram → «Открыть меню Арти», `/menu`, `/arti_commands` или сообщение «Меню». `/start` включает ответы и открывает меню. При запуске приложение устанавливает короткую командную навигацию Telegram; старые команды остаются совместимыми техническими входами.

Главные разделы: «Создать», «Материалы», «Проекты», «Задачи», «Совместная работа», «По расписанию», «Память», «Настройки», «Как пользоваться». Тексты и названия действий задаются в `bot/menu/views.py`.

## Одно сообщение навигации

Переходы, настройки, вопросы формы, подтверждения и просмотр объектов редактируют одну панель пользователя в текущем чате и теме. Есть «Назад», «Меню», предыдущий шаг и отмена ввода. Файлы, аудиоотрезки и готовые результаты отправляются отдельно, поскольку их нужно сохранить или скачать. Выгрузка результата сохраняет доступные кнопки его панели; выбор формата не возвращает пользователя преждевременно на исходный экран.

Явный запрос `/menu`, `/arti_commands` или сообщение «Меню» всегда открывает новую панель внизу разговора. Предыдущие кнопки отзываются на сервере и убираются из старого сообщения; ошибка очистки старого сообщения не блокирует новое меню. Повторная доставка того же запроса не создаёт вторую панель. Переходы «Назад» и «Меню» внутри клавиатуры продолжают редактировать текущее сообщение. Чужой клик по общему разделу открывает рабочую панель нажавшего пользователя. Одновременно могут существовать личные рабочие панели нескольких участников.

Навигационные `send_message` и `edit_message_text` вызываются без автоматических повторов RetryBot. После сетевой неопределённости новая панель автоматически не создаётся. Подтверждённое отсутствие сообщения допускает замену только по явному открытию меню. Старые кнопки и повторная доставка одного native update не запускают действие второй раз. Ошибка «message is not modified» считается подтверждённым отсутствием изменения, а не поводом отправлять ещё одно сообщение.

## Разделы и формы

| Раздел | Возможности |
| --- | --- |
| Создать | Картинка, видео, музыка, инфографика, многошаговая задача, учебный сценарий; дубляж и работа с голосами. Старые пошаговые клавиатуры генерации преобразуются в inline-кнопки. |
| Материалы | Таблицы и качество, 12 видов расчётов, исправление ячейки, поиск, авторская оценка файла, расшифровка, выбор аудиоотрезка и исправление текста, кадры и момент видео. |
| Проекты | Создание, выбор, цель, добавление файла, роли, архив/возобновление, удаление, предварительный просмотр переноса в группу. |
| Задачи | Состояние, обновление, результат или сохранённая часть, пауза/продолжение/отмена, новое задание, просмотр и отдельное разрешение внешнего действия. |
| Результаты проекта | Источники, данные, PNG/SVG/PDF, формат, принятие/отклонение, изменение заголовка и текста выбранного блока, удаление блока и восстановление версии. |
| Совместная работа | Предложение вариантов решения, позиции с причиной, явный выбор организатора; поручения конкретному участнику, срок, принятие/отказ/выполнение самим исполнителем. |
| По расписанию | Сохранение процедуры из собственной проверенной задачи, запуск, предложенная замена другим успешным способом и принятие; подписки, расписание, лимиты, последний выпуск, пауза/возобновление/удаление; сценарии и ответы на этапы. |
| Память | Профиль, состояние Арти, поиск исходной записи, поиск сведений для явного удаления. |
| Настройки | Модель, RP-сцена, оформление, инициативность в теме группы, тихие часы, лимиты, часовой пояс, реакции, новые темы, видимость и пробный режим; отдельное подтверждение управления всем чатом. |

Основные формы не требуют ID и JSON. Объекты выбираются по названию и состоянию, версии сохраняются в серверном действии. Для участника можно переслать сообщение с открытым автором; числовой ID остаётся запасным вариантом. Для группы назначения принимается пересланное сообщение, публичное `@название` или ID; аудитория и права повторно проверяются сервером.

Создание процедуры строит закреплённый рецепт и контрольный пример из сохранённого успешного выполнения, убирает старые разрешения и требует явного подтверждения. Новая процедура из этого пути повторяет выбранный проверенный способ с его входами. Для существующих параметризованных процедур форма поддерживает скалярные поля, вложенные объекты с известными полями и списки скалярных значений. Произвольные вложенные списки объектов и свободные JSON mappings остаются техническим входом; меню сообщает об ограничении до запуска.

Перед изменением формы показывают собранные значения. Сроки требуют часового пояса. Подписки поддерживают ежедневный запуск, будни или интервал, количество выпусков и лимиты вызовов/затрат. Большое внешнее действие просматривается по частям; кнопка разрешения появляется после последней части, а digest и версия проверяются повторно при согласии.

## Права и границы

Общими считаются только входные экраны с назначением возможностей. Состояние генерации, заполненная форма, просмотр объекта, его правки, подтверждение и внешнее разрешение — личные рабочие экраны.

Каждая кнопка содержит непрозрачный токен до 64 байт. Сервер хранит её владельца, chat/topic, persona/mode/scene, message ID, поколение экрана и срок. Токен не предоставляет прав сам по себе. При чужом клике по рабочей панели показывается короткое объяснение; состояние владельца не изменяется. Копирование callback data в другую тему или сообщение тоже не допускается.

Роли проекта и авторство проверяются при чтении и при мутации. Кнопки редактирования и принятия показываются по текущим правам; потеря права между просмотром и подтверждением отменяет операцию. Внешние grants принадлежат реальному пользователю и точному просмотренному составу. Сообщение панели от бота не записывается как высказывание пользователя: источником согласия служит настоящий native callback ID.

Старые кнопки фото, документа, обработки голоса и выбора модели дополнительно проверяют ID конкретной карточки. Наличие своего ожидающего запроса не разрешает нажать чужую карточку. Ролевую сцену нельзя открыть или закрыть кнопкой из группы. На клиентах Telegram inline-кнопка физически видна другим участникам; запрет клика обеспечивается серверной проверкой с коротким уведомлением.

В группе текст и файл принимаются в форму только от владельца и ответом на точное сообщение его панели. Разговор других участников продолжает идти своим маршрутом. В личном чате ввод принимается только при активном ожидаемом шаге; просмотр модели не перехватывает обычный разговор.

«Отменить ввод» очищает только ввод пользователя и его временные файлы. Эта кнопка не отменяет задания остальных. Явное открытие меню также освобождает его незавершённый ввод старых команд. `/cancel` сбрасывает долговечный draft/snapshot, чтобы последующее сообщение не восстановило отменённую форму. Остановка медиа-запросов всего группового чата требует администратора; персональные агентские задачи имеют свои кнопки управления. В собственном личном чате пользователь может запускать бота и управлять его настройками без группового статуса администратора.

## Хранение и восстановление

Миграция `027_telegram_menu.sql` добавляет `arti_menu_sessions` и `arti_menu_requests`. Один session соответствует chat/topic/user. PostgreSQL session advisory lock сериализует работу панели между workers, без открытой SQL-транзакции на время сетевого вызова. Одновременно удерживаемые menu locks ограничены третью локального пула, чтобы массовые клики не занимали все соединения и не блокировали собственные SQL-операции. Native requests потребляются один раз; старые записи очищаются через два дня. Неактивные sessions удаляются при открытии меню после истечения срока. Ввод ожидается до 20 минут; панель и кнопки действуют до суток после обновления.

Формы, выбранные объекты и известный message ID восстанавливаются из SQL. Длинное подтверждение делится на страницы без обрезания значений; «Выполнить» появляется на последней странице. В state сохраняются ограниченные Telegram metadata, не байты пользовательских файлов. Простые параметры генерации можно восстановить; несохранившийся образец изображения требует повторного прикрепления. Озвучка с временными файлами после перезапуска может требовать нового ввода. Такое состояние не превращается молча в другой запрос.

Фоновым media/text/dubbing/vclone jobs передаётся настоящий транспорт, а не редактируемая поверхность меню. Готовый результат не перезаписывает открытый впоследствии раздел. Agent processing card не регистрируется поверх сообщения меню; фоновые задачи сохраняют свои обычные delivery guards и квитанции.

## Активация и проверка

Меню устанавливается при обычном запуске приложения. Основные разделы генерации и общения используют существующие настройки. Материалы/проекты требуют `ARTI_MATERIALS_ENABLED=1`; исполнение агента и расписаний дополнительно требует `ARTI_AGENTS_ENABLED=1`. Выключенная возможность объясняет своё состояние до начала её формы. Реальные календарь, задачи и хранилище по-прежнему не подключены; меню не обещает внешнюю запись.

```text
python -m unittest tests.materials.test_menu -q
python -m tools.run_materials_tests --all
```

SQL-проверки требуют `ARTI_TEST_DB=1` и создают disposable базы. Transport doubles проверяют native payload, число отправок/редактирований, права, повторные clicks, восстановление, формы и реальные repositories. Они не заменяют проверку интерфейса на настоящих клиентах Telegram. Пилот, перенос рабочего DB и включение flags остаются отдельным эксплуатационным шагом.

После исправления повторного открытия меню: **44/44 проверок меню** и **65/65 в целевом наборе** вместе с agent acceptance и group ingress, без ошибок и пропусков: [отчёт](evaluation/telegram_menu_reopen.json). Последний полный прогон до этого исправления: **431/431** на коммите `ede4cde` ([общий отчёт](evaluation/materials_full_tests.json), [первоначальная приёмка меню](evaluation/telegram_menu_acceptance.json)). Эти числа не являются результатом живого Telegram-пилота.
