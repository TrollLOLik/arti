# Эксплуатация когнитивной модели

## Текущий режим и выбор модели

Рабочий бот использует только новую память, эмоции, отношения и намерения.
`ARTI_COGNITION_MODE` и `ARTI_COGNITION_MODEL` больше не читаются и не нужны в `.env`.
При запуске существующие обычные контексты и текущие RP-сцены автоматически
получают `active` через блокировку, смену epoch и отзыв старых leases.
Завершённые и `legacy-unresolved` RP-сцены остаются архивными.

Модель выбирается обычным меню Telegram или `/model`. Этот выбор используется
для интерпретации событий, диалоговых ответов (включая фото), арбитража группы,
составления её реплик и планирования агентских задач. Модель фиксируется на
время ограниченной последовательности повторов одного вызова. Изменение выбора
действует на последующие вызовы; работа в другом чате не меняет этот выбор.
Gemini использует имеющийся Google-клиент; остальные модели — настроенный
`OMNIROUTE_BASE_URL`/`OMNIROUTE_API_KEY`. Отдельный OpenRouter-ключ не требуется.
Неверный JSON или сбой провайдера не включают прежние charge/closeness/RAG.

Старый проактивный scheduler, извлечение событий/фактов, профили, консолидация,
эмоциональная интроспекция и случайные реакции отключены. Их совместимые API
возвращают пустой/retired результат без расчётов, записи и LLM-вызовов.
Исходные таблицы сохранены для переноса и удаления исторических данных.
Недавний диалог читается из разрешённых исходных событий и подтверждённых
доставок, с границами темы/сцены; старые выжимки и неподтверждённые ответы
в промпт не попадают. Транспортные анти-повтор и cooldown стикеров ведутся
по новой outbox и не начисляют эмоции.

Очистка обычного диалога сохраняет память и эмоциональное состояние, но ставит
границу истории и отменяет подготовленные ответы из прежнего контекста.
Очистка RP или `/cancel` закрывает текущую сцену; её источники и намерения
не возвращаются в новую сцену при перезапуске. Смена Telegram chat ID сохраняет
активную память, отзывает старые отправки и требует нового разрешения инициатив.

Политика самостоятельного участия группы остаётся отдельным разрешением:
`mentions/useful/social`, расписание, видимость, квоты и `shadow/live` относятся
к инициативам, а не к выбору старой памяти. Переход памяти в active сам по себе
не разрешает новые сообщения всем группам.

## Перенос и запуск

1. Сохранить резервную копию рабочей БД, не добавляя её в Git.
2. Проверить offline сценарии и перенос на отдельной копии:

   ```powershell
   python -m tools.run_cognition_tests
   python -m tools.cognition_admin verify-copy
   ```

3. Остановить обработку на время переноса рабочей истории:

   ```powershell
   python -m tools.cognition_admin migrate
   python -m tools.cognition_admin status
   ```

   Миграция использует фиксированный snapshot и checkpoint. Повтор продолжает
   тот же снимок. Подтверждённые исходные сообщения сохраняют авторство и lineage;
   неоднозначные записи идут в quarantine. Старые RP-сообщения остаются в сцене
   `legacy-unresolved`. Прошлые эмоции, авторство и обещания не выдумываются.

4. Запустить `python main.py`. Runtime сам активирует актуальные контексты.
   Для исправления отдельной сохранённой authority остаётся команда:

   ```powershell
   python -m tools.cognition_admin authority --chat-id 123 --mode default --value active
   ```

   Для группы указать её точный `--topic-id`, для RP — текущий `--scene-id`.
   Переключение в старую модель через эту команду больше не поддерживается.
5. Проверить backlog, dead-letter, rebuilding, provenance/owner gaps и выбранную
   модель на синтетическом вызове. Реальные наблюдения не экспортировать в отчёт.
   Оценка естественности поведения в живой переписке остаётся отдельной оценкой,
   а не следствием успешного offline прогона.

   ```powershell
   python -m tools.verify_selected_cognition
   ```

   Команда читает только выбор моделей рабочей БД и проверяет синтетические
   нейтральный запрос, ограничения каналов и сообщение о потере. Она не пишет
   наблюдения в рабочую память и не отправляет сообщения в Telegram.
   Если выбранная модель работает через локальный OmniRoute, шлюз должен
   быть запущен; отсутствие подключения не меняет выбор модели автоматически.

## Диагностика и восстановление

```powershell
python -m tools.cognition_admin status
python -m tools.cognition_admin retry-rebuild --context-id 3
python -m tools.cognition_admin cancel-unknown --outbox-id 17
```

`status`: очереди/доставки по статусу, authority, возраст готового backlog,
просроченные leases, provenance gaps, owner violations, число rebuilding contexts.
Любой provenance gap/owner violation требует остановки active-контекста.

`retry-rebuild` применим к заблокированной незавершённой пересборке. Обычные jobs
и доставка ждут за durable barrier; исходные источники не возвращаются из tombstone.
Задание восстановления сохраняется до удаления. После трёх неудач требуется
операторский retry после устранения причины. Он не вызывает внешних сообщений.

`cancel-unknown` закрывает неоднозначный слот, не отправляя его повторно.
Сначала оператор проверяет реальный Telegram-результат. Между Telegram и SQL нет
общей транзакции; неизвестный исход нельзя автоматически объявить недоставленным.

Jobs: lease 300 с, renewal 40 с, до трёх job attempts; интерпретатор — до трёх
попыток по 90 с внутри job. Верхняя граница — девять попыток на observation.
Worker drain — 20 с. Не использовать приватный текст/исключения провайдера как
last_error; допустимы только фиксированные категории.

`/my_profile`, `/charge` читают владельца в актуальном контексте.
`/memory_archive тема` явно проверяет исходную запись.
`/forget тема` предлагает один источник или все найденные owned источники.
Bulk selection содержит только IDs/owner/chat/TTL, не сохраняет запрос в памяти.
Сам `/forget` не кодируется как новая автобиографическая реплика.

## Восстановление версии

Автоматического отката на старую эмоциональную модель нет. При проблеме
исправить провайдера/выбранную модель, пересобрать разрешённые проекции либо
восстановить согласованную версию приложения и её резервную копию.
Удалённые источники и tombstones не сбрасывать. Неоднозначные Telegram-доставки
не повторять автоматически. Новые числовые состояния не преобразуются в charge.

## Повтор экспериментальных проверок

Offline numerical replay не расходует API:

```powershell
python -m tools.evaluate_full_cognition --split final_held_out --run-name frozen_final_v4
```

Live drivers — только синтетика:

```powershell
python -m tools.evaluate_full_cognition --split development --run-name next_development --live
python -m tools.evaluate_dialogues
python -m tools.evaluate_component_responses
```

Уже изученный final_held_out не является свежим hold-out для следующей настройки.
Новый научный цикл требует нового заранее выделенного корпуса и замороженных
критериев. `blind_packet.md` и `component_packet.json` допускают оценку людьми;
не показывать оценщикам отдельные файлы с ключами до завершения разметки.
Измерения модели не заменяют независимые человеческие оценки.
