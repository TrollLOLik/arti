## Результат второго пакета MA03–MA04

Реализован настоящий текстовый путь Mini App → существующий durable worker/process_user_reply → атомарный app-ответ. Telegram и Mini App используют один private/default контекст, очередь, память, persona и выбор модели. История обновляется через SSE с polling fallback. Посторонние исходные изменения сохранены.

| Батч | Реализация | Проверка |
|---|---|---|
| MA03 | Нейтральный channel/source key, message_id=None, атомарный source+message+job, общий FIFO, checkpoints/leases, UUID publication receipt, независимый Telegram mirror | Повторы/конфликты, rollback, два канала одновременно, crash после публикации, повтор без второго provider call, stale lease, неизвестное зеркало |
| MA03: комнаты | NativeContextKey/NativeAudienceScope, отдельный cognitive_native_contexts с начальным состоянием, явная сериализация и codec | Allocation/state/event/codec round-trip; private-аудитория не подходит native room, legacy identity сохранена; room inference закрыт до MA06 |
| MA04 | Backfill допустимых источников, реальные composer/job states, sources, пагинация/scroll, SSE/reconnect/polling, reset/revocation | >100 событий/равные времена/повтор переноса, разрешённые старые user sources, source erasure, reset до worker и до HTTP acceptance, logout открытого SSE |

Финальный общий серверный прогон: **123 теста — PASS**. Включены auth/HTTP, conversation repository/live chat, старый codec, request store/runtime/delivery, organizer ownership и cutover. После заключительной правки dependency locks/исторического фильтра выполнены 8 дополнительных адресных проверок публикации/shared history и проверка штатного закрытия открытого SSE при shutdown — PASS. Клиент: **28 тестов, TypeScript, ESLint, production build — PASS**. Python compileall, pip check и git diff --check проходят. Предупреждения aiohttp о RequestKey относятся к текущему способу хранения request metadata и не являются ошибками тестов.

Независимый browser evaluator дал **PASS** дважды. Первый проход: 320/375/390/768/1440, Enter/Shift+Enter, pagination/scroll, очередь/обработка/ошибка, точный retry после потерянного ACK, безопасный текст, reset/session expiry/revocation и отключённый demo. Второй проход после revision fence: настоящий API/SQL/worker на отдельной БД, отправки до/после reset, SSE и Telegram mirror metadata без второго пузыря; 390/1440, без runtime-ошибок. Доступен только один провайдер моделей, поэтому проверяющий использовал отдельный свежий контекст. Неблокирующее замечание: мелкие подписи времени/источника можно дополнительно укрупнить при последующей доводке.

Сквозной browser fixture использовал синтетический аккаунт, RecordedInterpreter и подставные provider/Telegram send. Проверены настоящие клиент, HTTP, PostgreSQL, worker и publication; платная модель и Telegram API не вызывались. Оба тестовых сервера 8779/8780 остановлены после проверки, временная browser DB удалена. Итоговые локальные снимки: `miniapp/qa/ma04-real-api-mobile.png`, `miniapp/qa/ma04-real-api-desktop.png`.

Важные исправления: dependency locks до request lane; повторное использование conn во вложенных helpers (включая organizer pending), чтобы конкурентные POST не исчерпывали pool; отключение app debounce; самостоятельная публикация без Telegram receipt; обязательный POST history_revision, который блокирует опоздавший ввод после reset даже пустой беседы. Organizer sources Mini App участвуют в единственной scheduling authority и существующем удалении.

**Границы:** `.env`, BotFather, рабочая БД и работающий бот не изменялись/не перезапускались. Миграции 056–058 применялись только в тестовых БД. Рабочий listener при последующем запуске использует active runtime бота и отдельный lifecycle для mirror, без второго poller. Preview 8767 остаётся пустым и без генерации. Реальные провайдеры, HTTPS, cookies/клавиатура/safe area на Telegram-устройствах ещё требуют проверки перед пилотом. Следующий пакет — **MA05–MA06: чаты людей и комнаты с Арти**.

## Проверенные серверные сценарии

Общий запуск: **44 теста — PASS**, в том числе 18 auth/HTTP, 10 контрактов/домена/БД и 16 существующих codec regression. DB-тесты создавали отдельные `arti_miniapp_test_<uuid>` и удаляли только их. Полная рабочая история и рабочие миграции не затрагивались.

- Подпись, изменённые/повторные поля, истечение initData, чужой бот и некорректный профиль.
- HttpOnly/Secure cookie в live-режиме, CSRF, Origin, вращение, logout и истечение серверной сессии. Header/query не заменяют авторизацию.
- Вход с тестовой Telegram-подписью через настоящий HTTP и PostgreSQL repository/session store; это не вызов реального Telegram.
- Несколько одновременных первых входов создают один основной чат пользователя.
- Повторы сообщения дают один ID/seq/event/outbox; другое содержимое с тем же ключом даёт конфликт.
- Искусственный отказ вставки outbox откатывает сообщение и счётчик последовательности.
- Порядок и пагинация при параллельных сообщениях; запрет reply на чужой чат.
- Чужие UUID не открывают историю, контекст или отправку; видимость комнаты начинается с вступления, отзыв закрывает доступ, повторный запрос не возвращает старую скрытую запись после нового вступления.
- Существующие private material/project scope key, identity key и realm совпадают после использования нового resolver.
- HTTP/domain импорт в отдельном процессе без AI-ключей не импортирует `config`/Groq.
- `pip check` и `git diff --check` проходят; Git сообщает только существующее предупреждение LF/CRLF в постороннем документе.

Для codec regression в отдельное окружение добавлен Pillow через `requirements-test.txt`; исходная среда Mini App его не содержала. Изменения в codec/движке для этого не потребовались. Общая регрессия всего бота и live-provider прогоны не заявляются: ядро и очередь в этом пакете не переделывались.

## Клиент и локальный запуск

Исходники: `miniapp/frontend/src/`. Сборка: `miniapp/frontend/dist/` (игнорируется Git, воспроизводится через `npm ci && npm run build`). Manrope и портрет локальны; внешний SDK — официальный Telegram WebApp.

Локальный сервер: [http://127.0.0.1:8767/](http://127.0.0.1:8767/), явная кнопка «Открыть локальный просмотр». Этот процесс изолирован от бота/БД. Сервер галереи на 8766 сохранён. Порт 8765 был занят отдельным статичным сервером, поэтому для нового клиента выбран 8767.

Данные preview пустые и принадлежат только текущей сессии. Это не импорт истории Telegram. Режим не включается при сбое входа в рабочую конфигурацию.

Независимая визуальная оценка — **PASS**. В первом проходе проверены 320/390/768/1440, light/dark/system, вкладки, недоступные действия, возврат из разговора, настоящий logout и перезагрузка. Выявлены и исправлены системная тема вне Telegram, доступные названия планшетной навигации и перенос прокрутки между разделами. Дополнительно исправлено сохранение старой ошибки при переходе на недоступный подраздел Space.

Повторный проход подтвердил все исправления: именованные ссылки на 768, browser light/dark при пустом initData, ручную тему, сброс прокрутки на 320, отсутствие переполнения/визуальных регрессий на 320/390 и отсутствие runtime-ошибок. Добавлены клиентские проверки theme fallback и версионных ограничений SDK. Локальные итоговые снимки сохранены в `miniapp/qa/`; отчёты независимой оценки — в task temp directory. Проверяющий использовал отдельный свежий контекст; другой провайдер моделей недоступен в текущем каталоге.
