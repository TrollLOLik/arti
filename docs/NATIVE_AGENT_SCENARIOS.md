# Нативные агентские сценарии Арти

Этот этап расширяет собственный органайзер и существующую работу с материалами. Он не добавляет внешние интеграции, не включает production-флаги, не исполняет произвольные обещания Арти и не меняет `videotrans` или несвязанные аудиосценарии.

## Основание и проверяемость

Код восстановлен заново на `master` `48033b0effab9c7210adc8b9f0526d35f27c17d6`, который уже включает PR #24. Утерянный локальный снимок не восстановлен побитово. Его прежние результаты тестов не считаются проверкой этого кода.

Свежие отчёты:

- `docs/evaluation/native_agent_scenarios.json`: целевые сценарии и независимые регрессии безопасности.
- `docs/evaluation/native_agent_validation.json`: полный набор обнаруженных тестов без исключения прежних тестов.

Каждый отчёт содержит исходный коммит, список хешей проверяемых исходников и общий SHA-256. Совпадение отпечатка до и после запуска обязательно. Текст документации и два выходных отчёта исключены из отпечатка, чтобы избежать самоссылки; исполняемый код, SQL-миграции, тесты, конфигурационные контракты и прежние JSON-данные для replay-тестов включены. Проверку выполняют после завершения правок исходников.

## Органайзер

Используется только собственное хранилище Арти. Личные записи доступны в личном чате владельца. Групповой запрос получает нейтральное предложение перейти в личный чат; данные из личного списка не показываются и не меняются.

Грамматика намеренно ограничена и детерминирована. Прямой текст пользователя отделён от цитируемого сообщения. Цитаты, чужие просьбы, отрицания и материалы не становятся разрешением выполнить действие.

Примеры (ID берётся из подтверждения или списка):

- «Добавь задачу купить хлеб», «Покажи мои задачи».
- «Напомни через 30 минут позвонить», «Покажи мои напоминания».
- «Переименуй задачу ID в Купить чай».
- «Перенеси напоминание ID на завтра» с последующим уточнением времени и пояса, если их нет.
- «Отмени напоминание ID», «Заверши задачу ID».
- Ответ на подтверждённое сообщение: «Перенеси это на завтра в 09:00». При непроверяемой ссылке бот попросит ID.

Недостающие параметры уточняются с сохранением состояния в PostgreSQL. Относительное время привязывается к исходной просьбе; ожидание часового пояса не сдвигает срок. Неоднозначное название не выбирается наугад. Для ссылки «это» требуется проверяемая связь с подтверждённым сообщением бота; непроверенная ссылка требует явный ID.

Сброс истории отменяет незавершённое уточнение и прежние ссылки на сообщения, сохраняя уже запланированные записи. Удаление исходного источника стирает зависимые записи и подготовленные ответы; служебные метки без содержимого не дают повторной доставке восстановить удалённое. Это распространяется и на старые записи без когнитивного события. При обновлении старые активные ответы органайзера без проверяемых связей с источниками консервативно отменяются; сохранённые задачи и напоминания остаются, а пользователю может понадобиться новая просьба. Другие обычные запросы эта очистка не отменяет.

Пересборка после удаления использует существующий механизм восстановления памяти. Он может консервативно очищать прежние `chat_history` и кеши личного контекста владельца, если их происхождение нельзя доказать по отдельным строкам. Исходные пользовательские когнитивные события остаются; сохранность каждой строки старого кеша не обещается.

Повторяющихся расписаний нет. Дедлайн задачи сам по себе не создаёт отдельное напоминание. «Заверши» относится к личной задаче; `done` у разового напоминания означает подтверждённую отправку уведомления, а не выполнение описанного дела. Неизвестный исход доставки не считается успешной доставкой и не запускает автоматическую повторную отправку.

## Задания по материалам

Идентичность нативной просьбы и исходный разрешённый набор материалов сохраняются до планирования. Повторный запуск не выбирает новые материалы из изменившегося текущего проекта. Модель предлагает план, но не расширяет доступ и не создаёт разрешения на действия.

Явно выбранные вложения имеют приоритет; если их нет, фиксируется снимок материалов текущего проекта. За один запрос принимается не более восьми материалов. Связанные workflows и стили проекта автоматически не подмешиваются: для них новый нативный запрос не получает подразумеваемое разрешение.

План и исполнение разделены: план сохраняется, затем новый исполнитель проверяет актуальные права и версии и выполняет разрешённые шаги. Сохранённая задача может быть обнаружена после сбоя передачи из обычного запроса без повторного создания. Неопределённые внешние эффекты и доставки автоматически не повторяются.

Совместимость обновления: ранее сохранённые задачи без новой привязки `native_request_id` сохраняют прежнюю семантику явно заданного плана и прежние проверки доступа. Восстановление находит ту же задачу, проверяет владельца и права проекта, не перепривязывает источники и не отправляет карточку повторно. Новый усиленный контракт замороженных источников не заявляется ретроактивно для этих задач.

Поисковые запросы во внешнюю сеть требуют прямой просьбы о поиске и ограничены непрерывной фразой исходного запроса вне цитат. Чтение явно указанной ссылки требует прямой просьбы открыть или проверить её; результаты разрешённого поиска могут служить ссылками для дальнейшего чтения. Запрет сети имеет приоритет. Текст материалов не даёт разрешение передавать извлечённые слова, секреты, ссылки или перекодированные строки третьей стороне. Произвольная переформулировка поисковой строки моделью не принимается как эквивалент разрешения.

## Воспроизводимая офлайн-проверка

Требуются зависимости проекта и отдельный disposable PostgreSQL. Не используйте рабочую базу бота. `ARTI_TEST_DB=1`, `DB_HOST` должен быть loopback, а `DB_NAME=postgres` указывает на управляющую базу отдельного временного сервера. Каждый SQL-тест создаёт и удаляет собственную `arti_cognition_test_<uuid>`.

```sh
python -m tools.verify_native_agent_scenarios --suite native
python -m tools.verify_native_agent_scenarios --suite all
```

Проверяющий скрипт отключает чтение dotenv, подставляет фиктивные ключи и блокирует внешние сетевые соединения. Для опубликованного отчёта дополнительно использована очищенная среда процесса и отдельный временный PostgreSQL 17. Все модельные и Telegram-ответы синтетические; проверка не измеряет живое семантическое качество, реальные задержки провайдера или поведение production-развёртывания.

## Границы

- Нет слияния, развёртывания или автоматического включения возможностей.
- Нет обхода существующих подтверждений инструментов и внешних действий.
- Нет чтения реальных переписок, секретов или рабочей базы данных.
- Уже начатую сетевую отправку нельзя отозвать задним числом; неопределённость сохраняется.
- Входящие данные до durable-приёма и ранее оговорённые ограничения транспорта остаются за пределами этого этапа.
