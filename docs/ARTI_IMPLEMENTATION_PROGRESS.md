## Внесённые изменения

В существующем пути исправлены собственное архивирование результата консолидации,
архивирование без принятой замены и потеря источников при Wiki-предложении.
Консолидация сохраняет владельца и entity-связи; смешение владельцев отклоняется,
устаревший план проверяется после LLM-вызова. Повторная запись отличается от новой
вставки. Dedup и уникальный индекс учитывают владельца и активный статус.

Прямой поиск возвращает факт при повторном вопросе без cooldown. Черновая Wiki
не участвует в поиске канона. Граф без mode/owner scope временно исключён из
извлечения до миграции. Поиск сущности охватывает весь текст. Резюме разговора
больше не становится самостоятельным фактом только из-за отсутствия фактов.

Диалог и память передаются в генерацию отдельно. Место для фактов и фрагментов
выделяется до профиля; обрезание по десяти/двадцати строкам удалено. Пользовательская
разметка экранируется, framing сохраняется. Пока это бюджеты символов; точное
соответствие токенизатору и полный бюджет сообщения ещё требуется.

Стикер меняет историю выражения, не начисляет настроение и не сбрасывает заряд.
Вход и sentiment имеют отдельные durable-ключи для сообщений с transport ID.
Повторный вход не получает повторный рост близости. Ответ-заглушка API не
используется для sentiment. NaN/Infinity не принимаются как emotional delta.
Пул БД публикуется после окончания миграции; при ошибке закрывается.

## Новый изолированный контур

`cognition/` содержит типы источников и контекстов, версии, appraisal, чистое
ядро с быстрыми эпизодами и медленным настроением, план выражения, SQL-репозиторий
с CAS, журнал причин и durable jobs с leases/backoff/dead-letter. Два задания
одного контекста не исполняются одновременно; позднее наблюдение не обгоняет
предыдущее, ожидающее retry.

У новых производных есть исходные источники. Удаление источника подавляет его
повторную регистрацию, очищает payload производных и заданий, пересчитывает
аффект по разрешённым свидетельствам. Производная наследует источники своих
родителей. Удаление одного участника сохраняет допустимые события другого.
Эти гарантии пока относятся только к новой схеме. Старые chunks/profiles/Wiki,
legacy `/forget`, caches и существующие фоновые задачи ещё требуют B04/B17.

Разбор смысла использует OpenRouter. LLM возвращает оценки измерений; метаданные
источника и версии привязывает код. Неполная вероятностная масса сохраняется как
явное неизвестное, не повышая достоверность оставшейся гипотезы. Системная ошибка,
replay и собственная реплика не считаются новым свидетельством о пользователе.

## Проверки и результаты

- Исходный адресный набор: 10 проверок, 9 провалов на отдельной PostgreSQL 18.1.
  [Baseline](evaluation/legacy_baseline.json) описывает воспроизведённые дефекты,
  а не общую оценку качества разговоров.
- [76 автоматических проверок прошли](evaluation/automated_tests.json) за 30,27 с:
  воспроизводимые проверки численного ядра, источников, CAS, конкуренции,
  забывания и legacy-регрессий находятся в `tests/`. Все внешние вызовы этих
  проверок подменены; реальные вызовы выделены в отдельный драйвер.
- [Финальный development-прогон](evaluation/development_uncertainty_v2_live.json):
  20/20 схем и критериев, 20 вызовов, p50 5,73 с, p95 14,39 с. p95 численного
  перехода около 0,14 мс.
- [Первый held-out-прогон](evaluation/held_out_uncertainty_v2_live.json): 8/8 схем,
  6/8 критериев, 8 вызовов, p50 6,10 с, p95 13,15 с. Параметры не менялись по
  результатам этого набора. Сохранённые восприятия позволяют повторить численный
  результат без API, включая два провала.

Первый live-прогон с 1800 токенами и default reasoning вернул допустимый результат
в 10/20 сценариях. Его статистика usage и задержки учитывала только успешные
результаты: для общей надёжности и стоимости она неполна. Следующие отчёты
учитывают также неудачные попытки. В каталоге модели default reasoning оказался
`max`; явный бюджет и корректное вероятностное представление устранили основной
структурный сбой. Промежуточные прогоны сохранены отдельно, не заменяют финальный.

У всех завершённых вызовов, чью стоимость сообщил провайдер, reported cost = 0.
Рабочая переписка не использовалась в live-прогонах. Это синтетическая инженерная
оценка; шкалы и коэффициенты не валидированы как психологические измерения.

Два held-out-провала существенны. «Ничего себе эксперт нашёлся» вызвало anger
0,233 вместо допустимого максимума 0,08; намерение было ошибочно сочтено
уверенным. Просьба ограничить проактивные сообщения вызвала суммарный импульс
0,85 вместо максимума 0,15. Следующая версия должна разделить предпочтение,
подтверждённый исход и атрибуцию намерения, с точными evidence spans и источниками.
Эти случаи после просмотра считаются изученными; для оценки новой версии нужен
новый отложенный набор. Pilot новой эмоциональной системы не открыт.

| B01 | Основные исправления реализованы и проверены; полный модельный токен-бюджет и оставшиеся интеграционные края ещё требуют работы. |
| B02 | Типы, версии и additive SQL-схема реализованы и проверены; перевод всех существующих записей и потребителей не завершён. |

| B06 | Чистые аналитические переходы и причинные эпизоды реализованы; unresolved concerns и архивирование разрешённых эпизодов не завершены. |
| B07 | Первичная оценка реализована; повторная оценка и более надёжное различение намерения/исхода не завершены. |
| B08 | Изолированный ExpressionPlan реализован; регуляция убеждений и согласованная доставка текста/голоса/стикера не интегрированы. |
| B09–B19 | Не начаты как законченные батчи; остаются обязательными частями общей реализации. |

## Воспроизведение

```powershell
$env:ARTI_TEST_DB='1'
$env:PYTHONIOENCODING='utf-8'
python -m unittest discover -s tests -t . -v
python -m tools.evaluate_cognition --split development --run-name uncertainty_v2
python -m tools.evaluate_cognition --split held_out --run-name uncertainty_v2
```

Последняя команда возвращает exit code 1 из-за двух поведенческих провалов.
Повтор численных результатов при этом воспроизводим. Интеграционные тесты создают
и удаляют только новые БД `arti_cognition_test_<uuid>`. Запуск бота и применение
новой схемы к рабочей БД в этой волне не выполнялись.
